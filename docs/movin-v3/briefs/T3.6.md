## Design (decided)
- **Entry point:** `app/eval/chateval.ts`, run with `node eval/chateval.ts [-saved] [-model id] [-docs] [fixture]`. Add it to the tsconfig `include` and to lint.
  - **Flags:** `-saved` resolves the saved connection, which needs the app's S3 settings and `SETTINGS_SECRET`; settings and the bucket are **read only**.
  - Without `-saved`, it uses `LLM_*` from the environment. Go's missing-connection text applies, minus "Claude".
  - `S3_BUCKET` defaults to `unused` when unset, as in Go.
- **Entries:** in memory only. Use the entries service on a memory store, `Replace`d from the fixture. Every case runs on the **same** document, in order, as in Go. It **never** writes to S3; prove it with a test that uses a store which throws on any write outside memory.
- **Agent:** one `openAgent` on a temp-dir SQLite file per eval run.
  - Each case is a **fresh conversation**: key `eval:<n>`, so each is a one-message conversation, as in Go.
  - Actor: `{ by: "chat-eval", channel: "web" }`, or `"telegram"` with `group: true` for case 12.
  - Model `-model` overrides the saved or env model id for the run.
- **Silence:** Go's `res.Silent` for `NO_REPLY` in a group must map through `reply.ts`. If `reply.ts` has no silent rule yet, add it there (shared with T4) with a test: exactly `NO_REPLY` (trimmed, as in Go's rule) in a group means silent.
- **Cases:** copy them verbatim, in order, with the same pass conditions and helpers (`live`, `added`, `unchanged`, `nextDec5`, `fridays`, `milestones`, `diff`). The 5 doc cases sit behind `-docs`, which builds the read-only docs library and viewer on the bucket. `lastLog` is the `agent tool call` lines logged during the case.
- **Output:** Go's per-case block and totals line byte-for-byte in shape:
  - the banner is `chat-eval: openai model <m> at <url>, <effort>, today <date>`;
  - the `usage:` line;
  - `PASS` or `FAIL  <reason>`;
  - `totals: …`, with prompt equal to in + cacheRead + cacheWrite;
  - the tool-call dump on failure;
  - the final line, either `All 12 messages produced the right change.` or `%d of %d messages made the wrong change`, with exit code 1 on failure.
  - Usage comes from the adapter's per-round `llm call` data; expose a per-run usage sum in `RunResult` if it isn't there.
- **Make targets:**
  - `app/Makefile`: `chat-eval` runs `node eval/chateval.ts` in the `app-test` image, passing the env through `-e` names only. `chat-eval-docs` does the same with `-saved -docs`.
  - Don't touch the root `Makefile`: Go stays frozen until T7. Record in `decisions.md` that removing `chat-eval-claude` happens at T7.

Also test:
