# T5.2: docs notice and the durable daily trigger

## Goal
Bring two Go behaviours over:
- the Telegram "Documents updated" group notice after a sync that changed something;
- the daily 03:00 document sync, run as a durable `movin.schedule` spec (T5.1b), so it survives restarts and catches up.

The startup sync, the minute refresh and `/sync` stay in-process, as today.

## Decided
- **Do exactly T5-plan §4 "T5.2".**
- **The send:** notices go through `agent.deliver("tg:<group>", {chat, messageId: 0, group: true}, parts)`. Notices from before the agent is open are held, at most 8, and flushed on `attach`. No pending note; Go adds none to the model context.
- **Wiring in `main.ts`:**
  - The docs spec goes into the same `schedules` list as the check-in spec.
  - With no Telegram token, there is no notifier, but the daily spec still runs, because Go syncs docs without a bot.
  - Re-read `main.ts` before editing; small `edit` calls only.
- **Settings:** if the docs schedule comes from settings that the admin page can change, call `rearm("docsync")` after a save, the same way as `rearmCheckin`. If it doesn't, say so.
