## Converter (`poppler.ts`)
- `createPoppler({ timeoutMs?, textTimeoutMs?, maxOutput? })` returns `{ text(pdf, signal?): Promise<Page[]>; render(pdf, page, region | null, longEdge, signal?): Promise<Uint8Array> }`.
- The defaults are 60 s, 30 s and 16 MiB. The tool commands and arguments must be exactly Go's (spec §3), using `pdfinfo`, `pdftotext` and `pdftocairo`, with stdin/stdout only and no temp files.
- Use `node:child_process` `spawn` with `stdio: ["pipe","pipe","pipe"]`.
- Port `fake.go` as a test helper only if the Go tests use it.

Behaviour to match exactly:
- **One slot per instance:** a promise-chain mutex. Waiting for it respects the caller's signal, and the error on abort is `"<tool>: waiting for the PDF tools: <reason>"`.
- **Timeouts:** on timeout or abort, SIGKILL the direct child only, as Go does (trap 1). Then don't wait for stdout to end: destroy the streams and settle within 2 s even if a grandchild keeps the pipe open. Use Go's error text, for example the timed-out message; copy it from `poppler.go`.
- **Output cap:** count bytes in the `data` handler, keep the first `maxOutput` bytes, and don't kill the child. Raise the cap error only if the exit status was 0, with Go's exact message.
- **Errors include the last stderr line,** exactly as `poppler.go` builds them.
- **Text:** decode `-enc UTF-8` output, split on `\f`, and parse the bbox layout to words exactly as Go does, including the HTML unescaping of word text (`&amp;` etc.; write a small unescape for the five XML entities plus numeric ones, and check what Go's `html.UnescapeString` handles in the cases the tests cover).
- Lengths and limits are counted in code points.
