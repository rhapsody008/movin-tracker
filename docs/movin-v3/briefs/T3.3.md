# T3.3 — The eight tools

## Goal
Port Go's agent tools as adapter `ToolSpec`s. This covers the entry tools, the document tools and the view tool, along with:
- the actor (who is asking) for writes;
- replay-safe change IDs;
- the per-run image cap and placeholders for earlier images;
- change lines carried through to `RunResult` and history;
- the `agent tool call` log line.

There is no prompt yet (that is T3.4) and no routes (T3.5).

## Design (decided)
- **Files.** `src/agent/tools.ts` holds the entry tools and `src/agent/doctools.ts` the docs and view tools. A `buildTools({ entries, docs, viewer, vision })` returns the `ToolSpec[]` in Go's order: 5 entry tools, then the 2 document tools when docs are on, then `view_document_page` when a viewer is present and `cfg.vision` is set.
  - None of these files imports pi-durable.
  - Schemas are written as literal JSON objects that serialise to Go's bytes.
- **Golden.** The `tools` array the stub receives through the adapter must equal, byte for byte, the `tools` array in Go's `internal/agent/testdata/openai_requests.golden:2`, after a `goMarshal` re-encode if pi-ai reorders keys. If pi-ai changes the wire shape of tools, for example by adding `strict` or reordering `function` keys, record the exact difference and compare the `function.{name,description,parameters}` bytes instead. A description, enum or property order differing from Go is a failure.
- **The actor.** `Agent.submit(key, text, { actor: { by, channel } })`. The adapter stores the actor with the submitted input, for example in the input entry's `data`, so it survives a crash and replay, and gives `execute` `ctx.actor`. Find the pi-durable mechanism in `durable-api.md` §3 and the `.d.ts`; record which one you used.
  - The **auth hook** is the adapter's `beforeTool`: a write tool (`add_entry`, `update_entry`, `set_dates`, `undo_change`) with no actor is blocked with `writes need a known person; this message has none`. Read tools are never blocked.
- **Change IDs.** `replayChangeId(`${epoch}|${taskId}`, index, args)` from `entries/ids.ts` goes through the service's `Replay`. `index` is the position within the call: one per created entry for `add_entry`, 0 otherwise. A rerun returns the earlier record and writes nothing.
  - `set_dates` is journaled, as the plan says, but its change line still has **no id**, as in Go. Check that the entries service supports journaling a meta change; if it doesn't, stop and report.
  - Write tools are `replay: "safe"`, and so are read tools.
- **Results.**
  - Every handler returns Go's JSON via `goMarshal`/`Ordered`; the field order follows `agent-spec.md` §2.3.
  - An error is a **result**, not a throw: `{"error":"<message>"}`, with Go's texts verbatim.
  - Unknown tools and invalid JSON arguments are handled by pi-durable (`tool_unavailable`, `invalid_arguments`). Assert what the model actually receives and record it as a known difference from `unknown tool "teleport"` and `arguments are not valid JSON: …`.
  - A blank arguments string becomes `{}`, if pi-ai hands one through.
- **Change lines.**
  - `ToolSpec` results gain `changes?: { id?: string; text: string }[]`. They come from `changetext.ts` and nothing else.
  - The adapter persists them with the tool result (e.g. `api.details`).
  - `RunResult` gains `changes` (in call order, `[]` when there are none, and kept when the run fails, as Go does) and `toolsUsed: string[]`, so that T3.5 can apply Go's `lookedInDocs` rule.
  - `history()` items carry the changes of their run.
- **Images.**
  - The cap is `MAX_IMAGES_PER_RUN = 6`, counted from the current run's durable tool results, so a replay counts correctly. Over the cap, the result is exactly `{"error":"image limit for this message reached; answer from what you have seen"}` and the image is dropped.
  - The adapter's `transformMessages` replaces image parts that come **before the current run's input** with the text `[image from an earlier message]`; record the sentence. This includes the extra user message pi-ai adds for tool images.
  - The view result is Go's JSON plus one PNG produced by `docs/render.ts`. If the viewer or crop rendering isn't ported yet, port it from `internal/docs/render.go` within this step, with tests, as T1 did for conversion.
- **Log line.** Each call logs Info `agent tool call` with `by`, `channel`, `tool`, `args` (raw) and `result` (cut to 2000 runes plus `…`, using a code-point cut). Never log the key. Images are not logged.
- **`stripSpecialTokens`** is applied to the final answer text in `RunResult`, as Go does.

## Tests
Use faux where possible; a temp SQLite file; and the stub for wire assertions. Port the Go tests that §7 assigns to T3.3, with Go names in the titles:
- `TestToolErrorsGoBackToTheModel`
- `TestAddEntryProducesChangeLinesWithUndoIDs`
- `TestUpdateSearchAndArchive` (stray keys ignored)
- `TestUndoChangeWithoutIDUndoesCallersLatest`
- `TestSetDates` (bare `"ok"`, no id)
- `add_entry` truncation at 30
- `search_entries` limit 30
- the document tool errors (`TestDocumentToolErrors`)
- the page truncation at 8000 runes and the no-text-layer note
- `TestViewDocumentPage`: 7 calls give 6 images plus the limit text; the region is echoed; with no vision there is no tool
- the empty answer after a document search: expose `toolsUsed`; the reply text itself belongs to T3.5
- the golden tools array

New tests:
- **Crash between write and reply:** in a child process, SIGKILL after `add_entry` has written but before the answer. After restart there is exactly one journal record and one created entry, and the run answers once.
- The placeholder replaces images from an earlier run, and the images of the current run stay.
- The actor is persisted across a crash; a write with no actor is blocked; a read with no actor runs.
- `changes` is kept on a failed run.

Mutations: at least 10, on copies, each failing a named test. Examples:
- tool order swapped;
- one description edited;
- replay ignored, so the write happens again;
- the image cap set to 7;
- placeholders also hitting current images;
- the actor not persisted;
- `set_dates` given an id;
- an error thrown instead of returned;
- the undo without an id not filtered by `by`;
- the add truncation removed.
