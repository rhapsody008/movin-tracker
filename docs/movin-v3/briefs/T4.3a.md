## Design (decided)
**`split(text, n)`:** Go's `bot.go:615-636` exactly, on code points.
- Prefer the last `\n` in `(n/2, n]`.
- Trim trailing `\n` from the chunk and leading `\n` from the rest.
- `split("", n)` returns `[""]`.
- `MAX_MESSAGE = 4000` (Go's, not the plan's 4096).

**`truncate(s, n)`:** Go's `:638-644`. At most `n` runes, the last one replaced by `…`.

**`changeText(changes: WireChange[])`:** `"• " + text` per change, joined with `\n`.

**`undoKeyboard(changes)`:**
- `null` when no change has an id.
- At most 8 buttons, 4 per row.
- The label is `Undo` for exactly one id, else `Undo 1`…`Undo 8`.
- `callback_data` is `undo:<id>`.
- Throw if any `callback_data` would exceed 64 **bytes** (UTF-8). Go never checks this; it guards v3's id format, which gives 31 bytes.

**`replyMessages(reply: ChannelReply, address: {chat: number; messageId: number; group: boolean}, options?: {timedOut?: boolean})`** returns `SendMessage[]`, or `null` when nothing is sent:

| Case | Text |
|---|---|
| `silent` | `null` (no message, no failure line) |
| `outcome.ok` | `reply`, then when there are changes `"\n\n" + changeText(changes)` (`bot.go:452-456`). Leading blank lines are trimmed before sending; the rest of the bytes are unchanged. Check whether `reply` can still start with blank lines after `shownText`'s trim, and pin it in a test either way. |
| `!outcome.ok` | `FAILURE_PREFIX + truncate(detail, 300)`, then when there are changes `"\n\nSome changes were saved before it failed:\n" + changeText(changes)` |

- **Detail on failure:** `detail` is `outcome.error`.
  - With `options.timedOut`, it is `TIMED_OUT_DETAIL = "the turn took longer than 15 minutes and was stopped"` instead of Go's `context deadline exceeded`, a recorded difference.
  - A plain `STOPPED_REPLY` (an abort that wasn't the watchdog) keeps `Stopped.` as the detail.
- **Message shape:**
  - The text is split with `MAX_MESSAGE`; each part is `{chat_id, text}`.
  - The first part gets `reply_to_message_id: messageId` **only when `group`**.
  - The keyboard (`undoKeyboard(changes)`) goes on the last part only, when not null.

**Fixed lines,** exported constants with Go's exact text:
- `NON_TEXT_REPLY` = `I can only read text for now. Drawings, photos and voice notes are coming.`
- `THINK_HINT` = Go's bare-`/think` answer (`commands.go:54-57`).
- `FAILURE_PREFIX` = `Sorry, that didn't go through: `.
- `NOT_CONFIGURED_DETAIL`: Go's text when no LLM is configured, if the bot path has one. Find it in Go and cite it; if there isn't one, say so and leave it out.

**Shared module:** if any text is shared with the web (`agent-spec.md:1186`), import it from `reply.ts`; don't copy it.

**Dependencies:** `format.ts` may import `src/agent/reply.ts`, `src/gostr.ts` and `client.ts` types. It must not import pi-durable.

## Tests (`format.test.ts`)
- **Ported:** `TestSplit` and `TestUndoKeyboard` (`bot_internal_test.go`), under their Go names, with every case.
- **Golden:** a Go generator `app/golden/t43/main.go` (`//go:build ignore`) calls Go's own `split`, `truncate`, `changeText`, `undoKeyboard` and the reply and failure assembly. These are unexported, so copy the functions verbatim into the generator with a comment citing `bot.go` lines, the way `t34` did, and keep that honest.
  - Inputs: emoji, CJK, `é`, a 9,000-rune text with and without breaks, breaks exactly at `n/2` and `n/2+1`, trailing and leading newline runs, 1, 8 and 10 changes, a failure with and without changes, and a 301-rune detail.
  - The output is `app/src/telegram/testdata/format.go.json`, and the TS output must be byte-identical.
- **Table over `replyMessages`:**
  - answered;
  - `Done.`;
  - refusal;
  - cut-off with text;
  - cut-off before text (failure);
  - failed with changes;
  - failed with `STOPPED_REPLY`;
  - `timedOut`;
  - silent → `null`;
  - private (no `reply_to_message_id`) vs group (first part only);
  - 2 parts with the keyboard on the last;
  - `set_dates`-only changes (no keyboard).
- **Request bytes:** a `goMarshal` of each `SendMessage` in the group/2-part case matches the bytes Go's client would send. Reuse T4.1's `requests.go.json` shape.
- **Mutations (at least 6):**
  - the keyboard on the first part;
  - split by UTF-16 units;
  - the `(n/2, n]` window off by one;
  - the newline not consumed;
  - threading in private chats;
  - `truncate` keeping `n` runes plus `…`;
  - `Undo` vs `Undo 1` for a single id.
