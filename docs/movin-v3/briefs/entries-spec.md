## 3. Service mechanics

- **Caching**: single in-memory `Doc` + ETag; `Current` never hits the store once loaded. `Snapshot.Doc` is the *live* cached pointer (comment "Callers must not modify it", `service.go:170`). Mutation results point at the same new document that was cached.
- **ETag read-modify-write** (`service.go:244-280`): `writeMu.Lock` → `Current` → `base, etag`; loop `attempt = 0…`:
  1. `d = base.Clone()`; `fn(d)` (reset of `res` happens inside `fn`, so a retry discards partial results);
  2. `json.Marshal(d)`; `Put(Key, body, etag)` (If-Match semantics; empty etag = create-only `If-None-Match: *`);
  3. success → `set(d, newTag)` (notifies subscribers) → return;
  4. error not `ErrPrecondition` → returned as-is (e.g. `objstore.ErrNotFound` = `object not found`);
  5. `attempt >= MaxRetries(3)` → log warn, return `ErrConflict` (`someone else just changed the entries`);
  6. else log info, re-read `base, etag` from the store, `set(base, etag)` and loop.
  → **4 PUT attempts total** (initial + 3 retries), **no backoff, no jitter, no sleep** — the retry is immediate.
- **Precondition failure** is only retried if the store says `ErrPrecondition`; anything else aborts. `ErrConflict` is the only user-visible 409 (server maps it, `server.go:213`).
- **`Refresh`** takes `writeMu.TryLock()` and **silently returns nil** if a write is in flight (`service.go:189-192`) — this is what prevents a stale poll from overwriting a newer write (test at `service_test.go:352`). It compares only ETags (via `Stat`).
- **`set`** (`service.go:142`): under `mu`, computes `changed := etag != s.etag`; if changed, pushes to every subscriber. Because the initial `etag` is `""`, the first load also notifies.
- **`sendLatest`** (`service.go:156`): never blocks — if the 1-slot buffer is full it drains one item, then sends; a slow subscriber only ever sees the newest snapshot. Cancelling unsubscribes but **does not close** the channel.
- **Concurrency**: `writeMu` serialises all writes in-process (held across the whole retry incl. network); `mu sync.RWMutex` guards `cur/etag/loaded/subs`; `Refresh` uses `TryLock` instead of `Lock`. Cross-process safety is the ETag only.

## 4. Journal

- `record()` (`journal.go:26-41`): `Change{ID: ulid, At: stamp(), By, Channel, Op, EntryID}`, plus **shallow value copies** of `before`/`after` (pointer/slice fields still shared with the live entry — safe because entries are only ever replaced, not mutated).
- Change IDs: independent ULIDs, same generator as entry IDs (`journal.go:27`).
- **Cap `MaxChanges = 200`** (`journal.go:15`); on overflow it keeps the **newest 200** and drops the **oldest** from the front (`journal.go:37-39`). Trimmed changes can no longer be undone → `ErrChangeNotFound`.
- `Recent(ctx, n, by)` (`journal.go:112-126`): newest-first (iterates the slice backwards), filters `c.By == by` when `by != ""`, stops at `n`. `n<=0` → nothing. Returns `nil` (JSON `null`), not `[]`, when empty.
- **`Undo`** (`journal.go:54-110`), inside `mutate`:
  1. Find the change by exact ID, first match from the front; absent → `that change is no longer in the history: <id>` (`ErrChangeNotFound`).
  2. `before == nil && after == nil` → `that change is no longer in the history: <id> (empty record)` (`journal.go:72`) — same error type.
  3. `cur` = entry currently at `EntryID` (or nil). **`sameEntry(cur, after)`** compares `json.Marshal(Clone)` of both (`journal.go:43-51`, byte equality, field-order sensitive). Not equal → `ErrUndoStale` = `that entry has changed since, so undo was refused` (returned bare, no id).
  4. Restore:
     - `before == nil` (undo a create) → **remove** the entry at `i`; `Result.Entries = [cur]` (the removed entry).
     - `i < 0` (undo a delete) → append `*before` **verbatim** (original `updated/by/channel` preserved, not restamped).
     - otherwise (undo an update) → `d.Entries[i] = *before` with `Updated/By/Channel` restamped to `now`/actor.
  5. Journal the undo itself: `record(d, a, "undo", entryID, cur, restored)` — `After == nil` for undo-of-create, else the restored entry. So **yes, undo is journaled and undo-of-undo works** (tested both directions), and consumes journal slots too.
- Refusals summary: change not in journal (incl. trimmed), empty record, stale entry. Note undo cannot "insert at original index": an undo of a delete appends to the end of `entries`.

## 5. Search

`Filter` (`search.go:13-29`): `kinds`, `rooms`, `statuses`, `category`, `tags`, `vendor`, `text`, `date_from`, `date_to`, `include_archived`, `milestone` (`*bool`), `limit` — all `omitempty`; these exact names are the agent tool args.

Algorithm (`search.go:60-127`):
1. Normalise once: `kinds/rooms/statuses/tags` → `ToLower(Fields-join " ")`, drop empties (`lowerAll`, `search.go:42`); `category`/`vendor` → `ToLower(TrimSpace(...))` **without** inner-space collapse; `words` → `strings.Fields(ToLower(text))`.
2. Per entry, reject if: `Archived && !IncludeArchived`; kinds set and kind not in it; rooms set and (room nil or not in it); statuses set and status not in it; `Milestone != nil && IsMilestone() != *Milestone`; category set and `!= category` (exact); tags: **every** requested tag must be present exactly (`hasAll`); vendor set and not a substring of lowercased `Entry.Vendor`; date range.
3. `inDates` (`search.go:98`): no bounds → match (undated included); otherwise requires `Date != nil` and inclusive **string** comparison `from <= date <= to`. No format validation.
4. Text: haystack = lowercased `title, notes, vendor, category, source, kind, tags joined " "` (+ `room`), joined with `"\n"` (`search.go:138`); every word must be a **substring**. No tokenisation of the haystack, no prefix/word boundaries, **no accent folding, no stemming, no scoring/weights** ("ranking" = recency only).
5. Limit: `<=0` → `DefaultLimit 50`; else `min(limit, MaxLimit 200)` (`search.go:30-31,110-114`). `Total` = all matches before the cut.
6. Sort: `sort.SliceStable` by `hits[i].Updated > hits[j].Updated` — plain **byte** string compare of RFC3339 → newest first; ties keep document order (`search.go:119`).
7. Results are `Clone()`d; `Entries` initialised to `[]Entry{}` so JSON is `[]`, never `null` (`search.go:121`). Total is on the struct, not the entries.

## 6. Agenda

`(*Doc) Agenda(today, since string) Agenda` (`agenda.go:30-63`), pure string date maths, **no time zone and no clock** — the caller supplies `today` (`sched.Day(now, cfg.Location)` in telegram, `checkin.go:196`).

- `today` must parse as `2006-01-02`, else return an empty `Agenda` (`Quiet()` true).
- `yesterday = today-1`, `floor = today-7` (`MaxAskDays = 7`, `agenda.go:10`).
- `since`: `""` or not a `ValidDate` → `yesterday`; if `since < floor` → `floor`. No upper clamp, so `since == today` is legal (everything past is overdue).
- Skip `Archived`, `Status == "done"`, `Date == nil`.
- `day == today` → **Today** (any kind).
- else if `Kind != task || day > today` → skipped (future tasks and future non-tasks dropped).
- else if `day >= since && day <= yesterday` → **Ask**.
- else if `day < since` → **Overdue**.
- Each list `sort.SliceStable` by `when(e) = date + " " + (time or "99:99") + " " + Created` (`agenda.go:66-72`) → by date, untimed last within the day, then creation order. Overdue therefore comes out oldest-first because of the date prefix.
- Entries are `Clone()`d. `Quiet()` = all three empty (`agenda.go:24`).

## 7. Milestones

Rules (`model.go:52-56`, `model.go:480`, `milestone_test.go`):
- `milestone` is a plain bool, patchable, **not nullable** (`setBool`); `IsMilestone()` = flagged **and** `status == "done"`. A flagged but unfinished entry is *not* a milestone but keeps the flag (survives decode: `normalise` only drops `completed`, never the flag — `milestone_test.go:106`).
- `completed` is a done-only day: set to the app-TZ "today" on the transition into done, kept on later edits, cleared on leaving done, re-stamped on a later re-done; explicit `completed` wins; explicit day while not done → `completed needs status done`; clearing the day of a done entry keeps the old day. Precedence table at `model.go:460-478`.
- Both are `omitempty`, so old files keep byte-identical JSON (`TestOldEntriesUnchanged`), and hand-edited `completed` on a non-done entry is dropped on read.
- Search: `Filter.Milestone *bool` — `true` keeps only milestones, `false` excludes them, absent = no filter (`search_test.go`/`milestone_test.go:130`).
- Undo restores flag + day because the journal snapshots whole entries (`TestUndoRestoresMilestoneAndDay`).

## 10. Traps for a TS port

1. **`omitempty` + field order**: `milestone`/`completed` must be *omitted* when false/nil **and** placed between `archived` and `by`. Everything else is always emitted, including `cost` nulls, `tags`, `archived:false`, `meta` nulls, and `before`/`after` nulls in journal records. `TestOldEntriesUnchanged` fails on any reordering.
2. **Two different "empty" states**: allocated-but-empty `[]` (`entries`, `changes`, `tags`, `SearchResult.entries`) vs `null` (`Recent` result, `Entry` values never passed through `NewEntry`/`normalise`). Go's `omitempty` on `[]string` omits *both* nil and empty — so a TS port must not rely on truthiness.
3. **Go zero values**: missing JSON keys decode to `""`, `false`, `0`, `nil` — never `undefined`. `str(null)` returns `""` (so `{"title":null}` → `title must be 1–200 characters`, not a type error); `setCost`/`setTags` treat `null` as "clear".
4. **Map iteration order**: `Patch.Apply` iterates a Go map. Outcomes are order-independent (kind is forced first, the date/time rule is checked at the end), but *which* error surfaces when a patch has several bad fields, and which unknown field is named, is **non-deterministic in Go**. Any single deterministic order in TS is a superset-compatible choice; don't write tests that rely on Go's randomness.
5. **`sort.SliceStable`**: stable, so equal `updated` values keep document order — must use a stable sort in TS (Array.prototype.sort is stable in modern engines, but spell it out) and compare `updated` as **strings** (never parse to Date).
6. **String comparison is byte-wise in Go, UTF-16 code-unit-wise in JS**: matters for `updated` ties, `since`/`floor`/`today` (ASCII dates — safe), and tag/vendor equality. Non-BMP characters would order differently; dates and RFC3339 are ASCII so practically equivalent.
7. **Time handling**: only two formats exist. `created/updated/at` = `Date.toISOString()` **without milliseconds** (`.toISOString().replace(/\.\d{3}Z$/,'Z')`) and always UTC. `date/completed` = `YYYY-MM-DD` in the **app time zone** (`TZ`, default `Asia/Singapore`, `config.go:79`), *not* UTC — `TestCompletedDayFollowsStatus` pins 23:30Z → next day. Go validates dates by real parsing (`time.Parse`), so `2026-02-30` must be rejected — `new Date()`/`Date.parse` will silently roll over. `Time` is `HH:MM` with `24:00` rejected.
8. **`Patch` values are raw JSON**: `{"title":5}` → `title must be a string`; `{"limit":2.5}` fails `int` unmarshal; `{"archived":"yes"}` → `archived must be true or false`. `1e3` is a valid cost. Keep the "raw JSON per key, distinguish absent vs `null`" design — an absent key must not be treated as `undefined`-clears.
9. **Number handling**: costs are float64 → Go prints shortest round-trip form (`18000`, `5400.5`, `1e+21` for huge, `-0` possible). JS prints `1e+21` too but differs for large integers and `-0`; avoid reformatting if byte-identical files matter.
10. **Aliasing**: `Snapshot.Doc` is the *cached* document (no clone) and `Mutation` results and journal `before`/`after` **share nested objects** with it (shallow copies in `record`, `service.go:283-285`/`journal.go:29-34`). The Go code is safe only because fields are replaced, never mutated. In TS, either deep-freeze the cached doc or clone on read, or a UI mutation will corrupt the cache and the journal.
11. **Unknown fields in `entries.json` are silently dropped** on decode *and* gone on the first write (whole doc re-marshalled). Same for unknown keys in journal records and inside `cost`.
12. **Journal cap applies to undo records too**; undo of a delete re-appends at the end (position not restored); undo of a create returns the removed entry in `Result.Entries`.
13. **`Refresh` returning `nil` while a write holds the lock** is load-bearing (test at `service_test.go:352`) — a port that awaits instead of skipping will resurrect stale state.
14. **Errors are strings the LLM sees**: copy them verbatim, including `1–200` (en dash U+2013), `HH:MM (24h)`, `at most N characters`, `each tag must be at most 40 characters`, the full room list inside `room must be one of …`, the kind list, and the `: <id>` / ` (empty record)` suffixes. Also keep the distinction: `ValidationError` (400) vs `ErrEntryNotFound/ErrChangeNotFound` (404) vs `ErrUndoStale/ErrConflict` (409).
