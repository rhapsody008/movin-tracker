## Blocker
1. **A saved key isn't bound to its URL when it is loaded** (`internal/settings/settings.go` `resolve`, ~287–306). Two ways it can reach another host:
   - A process with `LLM_KIND=claude` reads a stored `llm` section that has no kind, for example one written by an older build. It then sends the stored key, saved for another host such as the vMLX one, to `api.anthropic.com`.
   - A process with `LLM_CLAUDE_BASE_URL` set sends the saved Claude key to that URL.

   *Fix:* keep a stored key only if `SameOrigin(stored baseUrl, final BaseURL)`, and add tests for both cases.

   *Today's exposure:* low. ZY's dev app sets neither variable, and the saved settings are kind `claude` with the Claude key. Still a real breach of the rule.

## Major
2. **Builds with different `ConvertVersion` re-read everything back and forth.** `sync.go` requires an exact match, so dev and prod on different versions keep re-reading every PDF and re-running every summary (billed). An older build writing `index.json` also drops fields a newer build added. *Fix:* treat `Version >= ConvertVersion` as current; keep unknown fields, or refuse to write over newer records.
3. **A failed re-read hides a document, and its recovery is announced as "added".** If converting a previously OK document fails (a timeout or S3 error), it disappears from search, view and the prompt until the next sync. The next success then posts "1 added" to the group. *Fix:* on a failed refresh, keep the old OK record; decide added vs changed from "was it ever readable".
4. **Alpine 3.20 is end-of-life** (2026-04-01), so prod's poppler gets no security fixes. Tests also use Debian's poppler, a different version from prod's. *Fix:* a supported Alpine release, pinned by digest; consider running the convert tests on the production stage.
5. **`convert.Converter` has no users** (`docs.Converter` and `docs.Renderer` are the ones in use). *Fix:* delete it and assert against the docs interfaces.
6. **`agent.SystemPrompt` is used only by tests and duplicates `llm.joinSystem`.** *Fix:* delete it and its tautological test.
7. **`Syncer.run` is one 120-line loop (gocognit 68)**, and its retry path wastes paid work:
   - summaries from a redone attempt are lost;
   - failed documents are re-converted on every attempt;
   - running out of retries returns a raw `ErrPrecondition` where entries and settings return `ErrConflict`.

   *Fix:* split the loop, remember every per-document outcome across attempts, and use the conflict sentinel.

## Minor
8. `RefusalReply` says "Claude declined" on OpenAI-compatible connections too. Use neutral wording.
9. The search snippet slices the original text with byte offsets found in a lowercased copy. A few rare characters change length when lowercased (e.g. Ⱥ), which can panic, so that turn fails. *Fix:* search in rune space.
10. The web chat strips `/think` from the newest turn only. Earlier turns keep the "/think" text, which costs a cache miss.
11. The `pause_turn` resend can't happen (no server tools), and as written it would drop the first call's usage and content. Remove it or merge both messages.
12. The fallback lookup cache is package-level, and a lookup cancelled by its caller caches "no fallbacks" for 5 minutes for everyone. Don't cache when `ctx.Err() != nil`.

## Questions
- **Cache marks:** with documents on, there are exactly 4 (the API maximum), with no guard against a fifth. Add an assertion.
- **`docs/raw/` protection:** the app's IAM user can overwrite `docs/raw/*`, and versioning is off. Add a `Deny PutObject` on `docs/raw/*` for the app user, and upload with a different user?
- **Memory headroom:** bigger drawings could need more. `-bbox-layout` output can reach 64 MiB plus a copy, and the caches hold up to ~42 MiB of PDFs plus 24 PNGs, under the 256 Mi limit.
- **Poppler lock:** it ignores the request's context, so a chat view can wait behind a minute-long sync run.
- **Env key without `LLM_BASE_URL`:** it isn't bound to any URL (this predates the change), so it can now also go to the Claude origin.
