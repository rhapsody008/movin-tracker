# T3.1 — LLM layer on pi-ai (OpenAI-compatible only)

## Goal
The model layer that T3.2 (the durable adapter), T3.3 (the tools), T3.6 (chat-eval) and the docs summariser all use:
- a pi-ai provider built from the saved connection;
- per-turn thinking;
- one error surface that never carries the key;
- usage logging, and the docs summariser.

There is no agent loop yet; that is T3.2 and T3.3.

## Design (decided)
- **`src/llm/provider.ts`:** `llmModels(cfg: LLM) → { models, modelRef }`. It wraps pi-ai `createProvider({… api: openAICompletionsApi() })` and `createModels().setProvider(…)`, as in `t03.mjs`. The synthesised model entry:
  - `id` and `name` = `cfg.model`;
  - `api: "openai-completions"`;
  - `input: ["text","image"]` when `cfg.vision`, else `["text"]`;
  - `reasoning: true` and `compat: { thinkingFormat: "qwen-chat-template" }` (check the exact compat field names in the `.d.ts`);
  - `contextWindow: 128_000`, `maxTokens: 8_192` and a zero cost. Keep these values as named constants, each with a comment.
  - The key is resolved through `resolve: async () => ({ auth: { apiKey } })`. With an empty key, send **no** Authorization header. Prove it with the stub; if pi-ai can't do that, stop and report.
  - The timeout is `cfg.timeoutSec * 1000`, passed wherever pi-ai or pi-durable accepts it. Record where.
- **`src/llm/complete.ts`:** `complete(cfg, { system, messages, think, signal }) → { text, stop, usage }`.
  - It makes one non-agent call through pi-ai's single-shot API, for the summariser and chat-eval helpers. No tools.
  - Stop mapping follows Go's `stopOf`: tool calls → `tool`, `length` → `max_tokens`, `content_filter` → `refusal`, anything else → `end`. Map from pi-ai's `stopReason`, and record the mapping table in `decisions.md`.
- **Thinking:** `thinkingFor(cfg, think) → pi-ai thinkingLevel`.
  - `cfg.thinkOnDemand && !think` → off; the wire must carry `chat_template_kwargs.enable_thinking:false`.
  - Otherwise → the default level; the wire must not carry `enable_thinking:false`.
  - Assert the actual bytes the stub receives in both cases. Record pi-ai's exact kwargs, including `preserve_thinking` if it sends it.
- **Errors:** `llmError(assistantMessage | thrown, apiKey) → Error`. This is the only path by which a pi-ai failure becomes text.
  - The text goes through `scrubKey`.
  - When the HTTP status is recoverable from pi-ai, either from a field or by parsing its message (check what pi-ai exposes), produce Go's `endpoint returned <status>: <msg>` using the 300-char rules in `models.ts`. Otherwise keep pi-ai's message.
  - Record the exact texts for 401, 429, 500, 503 and a dropped connection in `decisions.md`, as known differences where they differ from Go.
  - **The retry classification must survive the mapping:** for every mapped text, pi-ai's `isRetryableAssistantError` (or the exported equivalent; find it) must give the same answer as for pi-ai's raw text.
    - Test that 429, 500, 502, 503, `other side closed`, `fetch failed` and `socket hang up` are retryable.
    - Test that 401 and `insufficient_quota` are not.
- **`stripSpecialTokens(text)`:** a port of Go's `StripSpecialTokens` (the regex and the trim). Test it with a Go golden table generated by a `tmp/t31-golden/main.go` harness; about 12 cases, including tokens mid-text, repeated tokens and only tokens. T3.3 applies it.
- **Usage log:** `logLLMCall(log, { model, round, stop, usage })` writes Go's `llm call` line with the fields `kind:"openai", model, round, stop, in, out, cacheRead, cacheWrite`. `cacheRead` comes from pi-ai's `usage.cacheRead`; `cacheWrite` is 0 unless pi-ai reports it. T3.2 calls it per round.
- **Images:** helpers to turn `{mediaType, data}` into pi-ai image content. With the stub, prove:
  - a user message with an image goes out as `content:[{type:"text"…},{type:"image_url"…}]` with standard base64;
  - a tool result with an image produces pi-ai's extra user message. Record its exact sentence as the known difference from Go's `Images returned by the tools above.`
- **Summariser, in `src/docs/llmsummary.ts`:** `createLLMSummariser({ settings, log })` implements `Summariser`.
  - It resolves the connection on every call. With no base URL or model it throws `no LLM connection configured`.
  - The request uses `SUMMARY_PROMPT` as the system prompt, plus the user text `File: <name>\n\nStart of the text:\n<text>`. It is not streamed and asks for no thinking: whether thinking is sent follows Go (`Think` false, so with `thinkOnDemand` it is off).
  - The answer goes through `tidySummary`.
  - Wire it into `createSyncer` in `main.ts`.
  - `MOVIN_DOCS=off` stays.
  - Port `TestLLMSummariser`.
- **No Anthropic code path:** prove that loading `src/main.ts`'s module graph loads no `@anthropic-ai/*` or other provider SDK (OpenAI, Google, Bedrock and so on).
  - Use a child-process test, e.g. `node --import` with a loader hook, or `process.moduleLoadList`, or inspect the loaded files. Pick what works on Node 24 and confirm it in the docs.
  - Also run `npm ls` for those packages and paste the output.

## Tests (stub, no network)
Use a `node:http` fake OpenAI endpoint in `src/llm/stub.ts`, test-only, reusable by T3.2–T3.6. It:
- records the method, path, headers and JSON body of every request;
- answers in scripted modes: plain JSON; SSE streaming with text deltas, tool-call fragments by index, a usage chunk and `[DONE]`; HTTP 401/429/500/503 with an `{"error":{"message":…}}` body; a mid-stream `error`; and a socket destroyed mid-response.

Port the `internal/llm` Go tests that §7 assigns to T3.1, adapted where pi-ai's wire differs (each difference recorded). At least cover:
- the request shape;
- think on and off;
- Bearer only with a key, and no `x-api-key` or `anthropic-version` ever;
- images, including from a tool result;
- streaming reassembly (text plus tool calls);
- the error texts and scrubbing (a key echoed in the error body never leaves);
- the retry classification table;
- the usage log line;
- the summariser;
- special tokens.

**Mutations:** at least 8, on container copies, each failing a named test:
- `scrubKey` removed;
- the think mapping inverted;
- Bearer sent with an empty key;
- the stop mapping swapped;
- `tidySummary` skipped;
- the status mapping dropping the status;
- the strip regex missing one token;
- image input always on.

## Live check (billed; approved for T3.1)

1. a short text turn with thinking off;
2. the same with thinking on;
3. a tool-call turn using the probe's `set_dates` tool;
4. an image turn using the 1×1 probe PNG;
5. one summariser call on a fixed short text.

For each, print the stop, the first 80 characters of the text, the usage and the latency. **Never print the key, and never print the full config.**

**Don't run it yourself.** The main session runs it with the real `.env`. Show it working against the stub instead, by pointing `LLM_BASE_URL` at the stub with an empty settings bucket on MinIO.
