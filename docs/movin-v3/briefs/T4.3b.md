# T4.3b: durable outbox (delivery task) in the adapter

## Goal
Give the durable adapter a channel-neutral **outbox**: a pi-durable task, `movin.outbox.delivery`, that sends an ordered list of parts through a host-supplied `send` function. It is at-least-once per part and survives crashes:
- a crash before a send means the part is sent after restart;
- a crash mid-send means at most that one part is sent twice, and never an earlier one.

T4.2a builds on it, creating the task in the turn's settle commit. T4.4 and T5 use `agent.deliver` directly.

Plan: `docs/movin-v3/briefs/T4-plan.md` §2.4 and §3 "T4.3b" (approved by ZY 2026-11-22). Library research: `docs/movin-v3/briefs/durable-delivery.md` §1–§3. Decisions: `decisions.md` "T4 plan change".

## Design (decided)
**Only `adapter.ts` imports pi-durable.** `adapter.ts` must still not import `src/agent` or `src/telegram` at runtime (`imports.test.ts`).

**New `OpenAgentOptions.outbox?: Outbox`:**
```ts
export interface Outbox {
  /** Sends one part. Throws OutboxError to steer the retry; any other error counts as transient. */
  send(address: OutboxJson, part: OutboxJson, signal?: AbortSignal): Promise<void>;
}
export class OutboxError extends Error { retryAfterMs?: number; permanent?: boolean }
export type OutboxJson = null | boolean | number | string | OutboxJson[] | { [k: string]: OutboxJson };
```
`OutboxError` and `OutboxJson` are exported from `adapter.ts`; the Telegram code maps its client errors onto them in T4.2b.

**The task `movin.outbox.delivery`,** registered in the existing `movin.agent` extension (`tasks:`):
- **Input:** `{ address, parts: OutboxJson[] }`, which never changes.
- **Checkpoint:** `{ phase: "send", next: number, attempts: number }`.
- **Each run of the phase:**
  - If `next >= parts.length`: terminal `completed {sent}`.
  - Otherwise call `outbox.send(address, parts[next], signal)`.
  - On success, commit `{next: next + 1, attempts: 0}`, so the same phase runs again.
- **On error:**

  | Error | What happens |
  |---|---|
  | `permanent` | terminal `failed`; the remaining parts are dropped. Log `outbox delivery failed` with the error (scrubbed) and `part`/`of`. |
  | `retryAfterMs` | a sleeping commit until `now + retryAfterMs + 1000`, `attempts + 1` |
  | anything else | sleep 1, 2, 4, 8, 16 s by attempt |

  After **6 attempts** on one part, the task ends terminal `failed`, as above. The numbers are constants (`OUTBOX_MAX_ATTEMPTS = 6`, `OUTBOX_BACKOFF_MS = [1000, 2000, 4000, 8000, 16000]`). The tests inject a clock or short values; use the adapter's existing `now` and timer injection if there is one, and say how.
- **Abort handler:** terminal `aborted`, sends nothing. T5.3's restore path needs this.
- **Never send from a commit callback.** A send happens outside the commit; only the checkpoint move is committed (`durable-delivery.md` §3).

**New `Agent.deliver(key, address, parts): Promise<void>`:**
- creates the task for conversation `key` in its own commit (create the conversation if needed, the same way `submit` does) and resolves once it is **created**, not sent;
- `parts.length === 0` is a no-op.

T4.2a adds the settle commit that creates the task together with its ledger change. Factor the "create a delivery in this tx" code so T4.2a can call it inside another commit.

**Restore hook for T5.3:** export nothing new yet, but keep the kind name a constant (`OUTBOX_TASK = "movin.outbox.delivery"`).

**Without `outbox`:** if `options.outbox` is undefined, `deliver` throws `no outbox configured`. The task kind is still registered, so a database with pending deliveries opens. Such a task waits with a long sleep and a warning log; it doesn't fault.

## Tests
**`adapter.test.ts`, with a recording fake outbox:**
- parts are sent in order, each once, with the same `address`;
- a 429-style `retryAfterMs` sleeps, then sends: inject the clock or wake, so the test needs no real 1 s waits;
- `permanent` stops the rest;
- six transient failures end in `failed`, with the 7th part never sent;
- an aborted task sends nothing;
- two `deliver` calls on one key keep their order: all of delivery 1 before delivery 2;
- `deliver` with no outbox throws;
- the Step 0 tests.

**`crash.test.ts`, with a new `crash-outbox-child.ts` modelled on `crash-tools-child.ts`.** The parent hosts a recorder (`node:http`) that the child's `send` POSTs to.
- **(a)** `send` writes a marker file and hangs **before** calling the recorder. SIGKILL, reopen with a normal child. Each part reaches the recorder exactly once.
- **(b)** `send` reaches the recorder for part k, then hangs before returning. SIGKILL, reopen. The recorder total is n+1: the duplicate is part k, and no earlier part repeats.

**`imports.test.ts`:** still green.

**Mutations (at least 5):**
- move `next` before the send;
- don't reset `attempts`;
- ignore `retryAfterMs`;
- send in the abort handler;
- off-by-one on the 6-attempt cap;
- send from inside the commit callback, if you can make it compile.
