## What to build

### `gojson.ts`: Go-compatible JSON text
`export function goMarshal(value: unknown): string` — `JSON.stringify(value)` (compact, no trailing newline) followed by Go's `encoding/json` HTML escaping: `<` → `\u003c`, `>` → `\u003e`, `&` → `\u0026`, U+2028 → `\u2028`, U+2029 → `\u2029`. These characters can only occur inside JSON strings, so a replace over the whole output is correct; say so in a comment. Then compare with Go on every other point the golden test can reach (control characters, `"`, `\`, non-BMP characters, numbers such as `18000`, `5400.5`, `0.1`, `1e21`, `1e-7`, `123456789012`). Where JS and Go differ (lone surrogates; `-0`), don't add code: list the difference in a comment and in your report.

### `model.ts`
Port of the model half of `model.go`, plain functions and plain data (no classes except `ValidationError extends Error`):
- Types `Doc { schema: number; meta: Meta; entries: Entry[]; changes: Change[] }`, `Meta`, `Entry`, `Cost`, `Change` (fields as in the spec §1; nullable Go pointers → `T | null`; `milestone: boolean`, `completed: string | null`). Constants `KINDS`, `ROOMS`, `TASK_STATUSES`, `PLAN_STATUSES`, `CHANNELS`, `SCHEMA_VERSION`, `STATUS_DONE`, `KIND_TASK`, `KIND_NOTE` (as `readonly` arrays / string constants in Go's order).
- `statusesFor`, `defaultStatus`, `validDate`, `validTime`, `normRoom` (returns `string | null`), `newEntry(kind)`, `isMilestone`, `cloneEntry`, `cloneDoc`, `findEntry(doc, id)` (returns a clone or `null`), `emptyDoc()`, `docView(doc)` (`{schema, meta, entries}`).
- `type Patch = Readonly<Record<string, unknown>>` — values are already-parsed JSON (what the HTTP body / tool args give). "Present" = `Object.hasOwn(p, k)`; present with `null` clears; absent leaves alone. This replaces Go's `Patch` (raw JSON) **and** `PatchFromMap`.
- `applyPatch(e: Entry, p: Patch): void` — mutates `e`, throws `ValidationError`; callers apply to a clone (as Go). Same rules and **exact messages** as the spec table (en dash U+2013 in `title must be 1–200 characters`). Go applies the non-kind keys in random map order; use one fixed order: `kind` first, then the remaining keys **in the patch's own key order**, then the time-needs-a-date check. Unknown key check first, over all keys, naming the first unknown key in patch order, quoted like Go's `%q` (`unknown field "colour"`; use `JSON.stringify` for the quoting and note in a comment where `%q` differs).
  - `str()` semantics: `null` → `""`; any non-string → `<k> must be a string`.
  - Numbers in `cost`: `typeof v === "number"` (JSON has no NaN/Infinity); booleans: `typeof v === "boolean"`, `null` is an error.
  - Lengths in **code points** (`[...s].length`), like Go's rune count.
- `settleCompleted(before: Entry | null, e: Entry, p: Patch, today: string): void` — exactly `model.go` (quoted in the brief's source): throws `completed needs status done`.
- `applyMetaPatch(m: Meta, mp: { moveDate?: string | null; keyDate?: string | null })` — a key present (`Object.hasOwn`) means "set"; `null` or `""` clears; otherwise `validDate` or the Go error message (read `model.go:524-548` for its exact text).
- `decodeDoc(text: string): Doc` — `JSON.parse` then build the doc **field by field with Go zero values** for missing or wrongly-typed fields (missing string → `""`, bool → `false`, pointer → `null`, array → `[]`, schema 0/missing → 1), unknown keys dropped, then `normalise` each entry exactly as `model.go:630-663`. Invalid JSON → `ValidationError`? No: Go returns a plain error `decode entries.json: <msg>`; throw `Error` with that prefix. Go's `json.Unmarshal` fails the whole decode when a field has the wrong JSON type (e.g. `"title": 5`); find what Go does for each type mismatch you handle and match it (the golden test below is the judge; if matching it exactly is impractical, list the cases and stop to report).
- `encodeDoc(doc: Doc): string` — `goMarshal` of objects built **in Go's field order** (spec §1), with `milestone` omitted when `false` and `completed` omitted when `null` (both placed between `archived` and `by`); everything else always present; `before`/`after` in changes `null` when absent. Do not rely on the input object's key order: build each object explicitly.
- Go's `strings.TrimSpace` / `strings.Fields` use `unicode.IsSpace`; JS `trim()` / `split(/\s+/)` use a different set (JS includes U+FEFF; Go includes U+0085). Write `goTrimSpace` and `goFields` with Go's set (`\t \n \v \f \r`, space, U+0085, U+00A0, and Unicode category Zs, U+2028, U+2029 — check Go's `unicode.IsSpace` doc in the Go stdlib inside the Go test image, `go doc unicode.IsSpace`) and use them everywhere Go uses TrimSpace/Fields. Lowercasing: use `toLowerCase()`; note in a comment the known differences from Go's `strings.ToLower` (U+0130, final sigma) — no special code.
