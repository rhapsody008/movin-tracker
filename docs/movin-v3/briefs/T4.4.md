## Design (decided)

### At-most-once and order
This is already given by T4.2b. Each command and callback is an intake item; the worker `take`s it first, then acts, so a redelivery or a crash never runs it twice.
- `plan.md:129` asks that `/undo` sent twice undoes two different changes. Pin it with two `/undo` updates in one batch, plus the same update redelivered.
- Command replies go out through `agent.deliver` with `textMessages`, which is durable and ordered behind the chat's earlier replies.
- `answerCallbackQuery` and `editMessageReplyMarkup` go through the client directly. They are ephemeral, and errors are logged and ignored, as in Go.
- A command that throws must not kill the worker. Port Go's `recover`: log `telegram handler panicked` and continue.

### Commands (spec §6, Go's exact texts)
- **`/start` and `/help`:** `helpText`, verbatim.
- **`/recent`:** Go's lines, with times in `config.tz` formatted `Mon 2 Jan 15:04`. Reuse an existing Go-layout helper if there is one; otherwise write a small one with a test.
  - It must tolerate an unknown op, such as a Go 1.0.x `meta` record, as Go's `recover` would. Decide the line: skip the record, or show a generic line. Go would drop the whole reply, which is worse. Record your choice.
- **`/undo`:** the caller's own latest change, using the actor name from auth check 2, with Go's four answers. On success, `↩ ` + the change line and a one-button keyboard, with no speaker prefix.
- **`/sync`:** spec §8.2 on the existing `Syncer`, with `counts` and `docList` ported exactly (§8.3).
  - "Documents aren't switched on" when there is no syncer (`MOVIN_DOCS=off`).
  - The reason is `telegram:<chat_id>`.
  - Wire the syncer into `BotOptions` from `main.ts`.
  - The group notice (`DocsChanged`) is **T5.2**. Don't add it, but make sure the reason prefix is what T5.2 will skip on.
- **`/checkin`:** `The check-in isn't available yet.` (main session's decision, `decisions.md` "T4 plan change") until T5.1. It stays in the menu.
- **`/think`:** already done.
- **Unknown command:** already done.

### Callbacks (spec §7)
- Auth check 2 refusal: already done in T4.2b.
- Routing:
  - `ci:` → answer empty (T5.1 replaces this);
  - `undo:<id>` → the undo flow;
  - anything else → answer empty.
- **The undo flow:** spec §7.2 exactly.
  - Go's three error toasts.
  - The success toast is `truncate(line, 190)`.
  - Drop the pressed button from the message's `reply_markup` as Telegram sent it back. When no rows remain, send `editMessageReplyMarkup(null)`, which T4.1 already sends as `{"inline_keyboard":[]}`.
  - Then the confirmation `↩ ` + (`name: ` in groups) + line, with its own Undo button, threaded in groups.
- **Check the T4.2b payload:** it must carry the callback's message id, chat, and `reply_markup` (Go reads `cb.Message.ReplyMarkup`). If it doesn't, extend it. Old ledger items without the field must still work; treat a missing field as no markup.
