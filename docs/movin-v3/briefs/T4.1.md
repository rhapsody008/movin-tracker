## Design (decided)
- **Types:** the types are the spec §1.1 tables, as TS interfaces with the same JSON names. Unknown fields are ignored. `int64` ids are `number` (Telegram ids fit in 2^53).
- **API:** `createClient({ token, baseUrl?, fetch?, maxDownload? })` returns these methods:
  - `getUpdates(offset, pollSeconds, signal)`
  - `getMe`
  - `sendMessage(msg)`
  - `sendChatAction(chatId)`
  - `answerCallbackQuery(id, text?)`
  - `editMessageReplyMarkup(chatId, messageId, markup|null)`
  - `setMyCommands`
  - `getFile`
  - `download(filePath)`
  
  Each method takes an optional `AbortSignal`.
- **Requests:**
  - Bodies are byte-identical to Go's JSON, with field order and `omitempty` as in Go. Use `goMarshal`/`Ordered`.
  - A null markup in `editMessageReplyMarkup` is sent as `{"inline_keyboard":[]}`.
  - `answerCallbackQuery` adds `text` only when it is not empty.
  - `getUpdates` sends `allowed_updates:["message","callback_query"]`.
- **Timeouts:**
  - `getUpdates`: `pollSeconds + 15` s;
  - `download`: 2 min;
  - everything else: 30 s.
  
  Combine the timeout with the caller's signal (`AbortSignal.any`). A body is read only up to 8 MiB.
- **Errors**, each with Go's exact texts (spec §1.3):
  - `TelegramApiError` has `method`, `code` (`error_code`, falling back to the HTTP status), `description` and `retryAfter`. Its message is `telegram <method>: <code> <description>`.
  - `isConflict(err)` is true for code 409.
  - The unreadable-body, decode-result and download errors (`telegram download: HTTP <code>`, and `file is larger than the download limit` for both the Content-Length check and the read check).
- **The token never escapes:**
  - Every error thrown carries only a scrubbed message: the token is replaced by `<token>` and the message is prefixed `telegram <method>: `.
  - It has **no** `cause` chain to the original error (the original fetch error quotes the URL).
  - The abort and timeout kind stays detectable: `err.name === "AbortError"` or `"TimeoutError"`, or an exported `isTimeout`/`isAborted`. This is Go's "unwraps only to `context.Canceled`/`DeadlineExceeded`".
- **No retries in the client.** Backoff belongs to T4.2.

## Tests (`client.test.ts`, fake API on `node:http`)
- Port every `client_test.go` test under its Go name, including `TestAPIErrors` (`RetryAfter == 7`), `TestTokenNeverInErrors` and `TestScrubControl`.
- **`TestTokenNeverInErrors`** walks `message`, `stack`, `String(err)`, `util.inspect(err, {depth: 10})` and every `cause`, looking for the token or any substring of it of 8 or more characters. Drive these through it:
  - connection refused;
  - a timeout;
  - a 502 HTML page;
  - a bad result;
  - both download failures.
- **`TestScrubControl`** shows that a bare `fetch` to the same URL does put the token in its error. If Node's own error doesn't quote the URL, show what does and say so.
- Request bodies are byte-compared with Go's. Take the expected bytes from a Go generator, `app/golden/t41/main.go` (`//go:build ignore`, run in the Go tools container), that marshals each request struct.
- **Mutations:** at least 6. For example:
  - the token left in the message;
  - `cause` kept;
  - `error_code` fallback removed;
  - `text` always sent;
  - the null markup sent as `null`;
  - the poll timeout without +15.
