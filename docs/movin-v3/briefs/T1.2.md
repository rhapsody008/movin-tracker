## API (`app/src/objstore/store.ts`)
One interface for both implementations (Go splits it into Store/Blobs/Describer only because Go interfaces are small; both Go implementations implement all of it):

```ts
export interface ObjectInfo { key: string; etag: string; size: number; lastModified: Date }
export interface StoreInfo { backend: "s3" | "memory"; bucket?: string; region?: string; prefix?: string; endpoint?: string; credentialSource?: string; credentialError?: string }
export interface ObjectStore {
  /** Body and ETag; throws NotFoundError. */
  get(key: string, signal?: AbortSignal): Promise<{ body: Uint8Array; etag: string }>;
  /** ifMatch = ETag: write only if it still matches. ifMatch = null: create only (If-None-Match: *). Returns the new ETag; throws PreconditionError. */
  put(key: string, body: Uint8Array, ifMatch: string | null, signal?: AbortSignal): Promise<string>;
  stat(key: string, signal?: AbortSignal): Promise<ObjectInfo>;           // throws NotFoundError
  delete(key: string, signal?: AbortSignal): Promise<void>;               // missing key is not an error
  list(prefix: string, signal?: AbortSignal): Promise<ObjectInfo[]>;      // every key starting with prefix, any depth, sorted by key (byte order); keys relative to the store prefix
  putBlob(key: string, body: Uint8Array, contentType: string, signal?: AbortSignal): Promise<string>; // unconditional
  info(signal?: AbortSignal): Promise<StoreInfo>;                         // never key material
}
export class NotFoundError extends Error {}
export class PreconditionError extends Error {}
```
Error messages: NotFoundError `object not found: <key>`, PreconditionError `precondition failed: <key>`. Both keep the original SDK error as `cause` when there is one. No other exports from `store.ts`.

## `app/src/objstore/memory.ts`: `export function createMemoryStore(): ObjectStore`
Same rules as `memory.go`: put with `null` fails if the key exists; put with an ETag fails if missing or different; every write (put and putBlob) gives a new ETag even for the same body (quoted, S3-like, e.g. `"` + md5(seq + body) + `"`); bodies are copied in and out (a caller mutating its array must not change the stored object); `lastModified` = write time; list sorted by key with plain `<` on strings (UTF-16 order is fine for our keys; note it in a comment if you rely on it); `info()` → `{ backend: "memory" }`. A plain object/closure over a `Map` is enough; no class needed.

## `app/src/objstore/s3.ts`: `export function createS3Store(o: { bucket: string; prefix: string; region: string; endpointUrl?: string; listPageSize?: number }): ObjectStore`
- `S3Client` from `@aws-sdk/client-s3` with `region`; when `endpointUrl` is set: `endpoint` + `forcePathStyle: true` (MinIO). Credentials from the SDK's default chain (pass none).
- Key = `prefix + "/" + key` when prefix is non-empty, else `key` (prefix trimmed of `/` by the caller, as Go's config does). `list` strips `prefix + "/"` from returned keys.
- `get`: `GetObjectCommand`, body via the SDK's `transformToByteArray()`. `put`: `PutObjectCommand` with `ContentType: "application/json"`, `IfMatch` or `IfNoneMatch: "*"`. `stat`: `HeadObjectCommand`. `delete`: `DeleteObjectCommand`. `list`: `paginateListObjectsV2` (with `pageSize: listPageSize` when set). `putBlob`: `PutObjectCommand` with the given content type, no condition. Pass `signal` as `{ abortSignal: signal }` to every `send` (check the option name in the `.d.ts` of `@smithy/types` / client-s3 and use the real one).
- Error mapping, as `mapErr` in s3.go: HTTP 404 or error name `NoSuchKey`/`NotFound` → NotFoundError; HTTP 412 or 409 or name `PreconditionFailed`/`ConditionalRequestConflict` → PreconditionError; anything else rethrown unchanged. Read the status from the SDK error's `$metadata.httpStatusCode` (confirm the field in the `.d.ts`). Write it as one small function used by every method.
- `info()`: `{ backend: "s3", bucket, region, prefix (omit if empty), endpoint (omit if unset), credentialSource }`. Credential source: resolve the client's credentials (`client.config.credentials()`); find out from the installed `.d.ts`/source of `@aws-sdk/*` / `@smithy/*` whether the resolved identity tells which provider supplied it (e.g. a `$source` / feature field). If it does, map it to Go's labels (`CredentialLabel` in s3.go: "env keys", "web identity (IRSA)", "shared profile", "instance role", "container role", "SSO", "unknown") with a small exported `credentialLabel()` function and port `TestCredentialLabel`'s table for the inputs that apply. If the SDK exposes nothing usable, stop and report what you found instead of inventing a heuristic. On failure to resolve: `credentialSource: "none found"`, `credentialError: "no AWS credentials could be loaded"` (never the SDK message, it can contain paths/profile names).
- Test-only helper `createBucket(store)` (bucket + versioning enabled, ignore "already owned/exists") lives in the test file, not in `s3.ts`.
