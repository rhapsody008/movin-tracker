## `app/src/log.ts`
The app's logger, JSON lines like Go's `slog.NewJSONHandler` (one object per line: `time` RFC3339 with ms, `level` `DEBUG|INFO|WARN|ERROR`, `msg`, then the fields): `export interface Log { debug, info, warn, error: (msg: string, fields?: Record<string, unknown>) => void }`, `createLog(opts: { level: "debug"|"info"|"warn"|"error"; write?: (line: string) => void })` (default write: `process.stdout.write(line + "\n")`), and `createTestLog()` returning `{ log, lines: string[] }` for tests. Nothing fancier.

## `ids.ts`
- `newUlid(nowMs?: number): string` — 26-char Crockford base32 (uppercase, alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`): 48-bit ms timestamp (10 chars) + 80 random bits (16 chars) from `crypto.getRandomValues`. Same shape as Go's `ulid.Make()`. Test: length, alphabet, time prefix sorts by time, decodes back to the given ms.
- `replayChangeId(key: string, index: number, args: unknown): string` — first 16 chars of Crockford base32 of `sha256(key + "|" + index)`, then the first 10 chars of Crockford base32 of `sha256(canonicalJson(args))`. `key` is `epoch|taskId` (the caller builds it). `canonicalJson`: JSON with object keys sorted recursively (arrays keep order), `undefined` members dropped. `node:crypto` `createHash("sha256")`. Export `REPLAY_PREFIX_LEN = 16`.

## `errors.ts`
Classes with Go's exact messages (spec §2/§4): `ConflictError` (`someone else just changed the entries`), `EntryNotFoundError(id)` (`no entry with that id: <id>`), `ChangeNotFoundError(id, emptyRecord?)` (`that change is no longer in the history: <id>` / `… (empty record)`), `UndoStaleError` (`that entry has changed since, so undo was refused`). `ValidationError` stays in model.ts. These are what the HTTP layer maps to 409/404/400 later.

## `service.ts`: `createEntriesService(o: { store: ObjectStore; log: Log; timeZone?: string; now?: () => Date })`
`KEY = "entries.json"`, `MAX_RETRIES = 3`. `timeZone` default `"UTC"` (like Go's `loc` default); `today()` = the date in `timeZone` as `YYYY-MM-DD` (use `Intl.DateTimeFormat("en-CA", { timeZone, year:"numeric", month:"2-digit", day:"2-digit" })` and check its output format in a test — en-CA gives `YYYY-MM-DD` on Node 24's full ICU; assert it rather than trusting it); `stamp()` = UTC RFC3339 **seconds** (`2026-11-12T23:30:00Z`). An invalid `timeZone` throws at construction (`RangeError` from Intl) — test it.

Methods (all `async` except `subscribe` and `startPolling`):
- `load()`, `current(): Promise<Snapshot>` where `Snapshot = { doc: Doc; etag: string }`, `refresh()`, `startPolling(everyMs): () => void` (setInterval, `unref()`, errors logged at warn, never thrown), `subscribe(listener: (s: Snapshot) => void): () => void` (called synchronously from the internal `set` when the ETag changes, like Go's notify; a throwing listener is logged, not propagated, and doesn't stop other listeners).
- `create(actor, patches, replay?)`, `update(actor, id, patch, replay?)`, `updateIf(actor, id, check, patch, replay?)` (`check(entry)` may throw; its error propagates unchanged and cancels the write; it re-runs on retry), `delete(actor, id, replay?)`, `undo(actor, changeId, replay?)`, `recent(n, by?)`, `setMeta(mp)`, `replace(doc)`. `Actor = { by: string; channel: string }`. `Result = { entries: Entry[]; changes: Change[]; snapshot: Snapshot }`. `replay?: { key: string; args: unknown }`.
- `snapshotJson(s)` → Go's wire form `{"doc":{schema,meta,entries},"etag":…}` via `goMarshal` (no `changes`).

Mechanics, exactly Go's (spec §3):
- One in-process write lock (a promise-chain mutex; write it, ~15 lines, no dependency) held across the whole retry loop. `refresh()` **skips and returns** if a write holds the lock (Go's `TryLock`) — load-bearing (trap 13).
- Retry loop: clone base, apply, `encodeDoc`, `put(KEY, body, etag)`; on `PreconditionError` re-read and retry immediately, up to `MAX_RETRIES` retries (4 puts total), then `ConflictError` (logged at warn); other errors propagate unchanged. The mutation function rebuilds its result from scratch on each attempt.
- `load()`: missing object → create the empty doc with `put(KEY, body, null)`; `PreconditionError` there → re-read and use the winner.
- **Aliasing (trap 10):** the cached doc is deep-frozen (`Object.freeze` recursively) before it is cached and handed out; `current()` returns the frozen doc; mutations work on `cloneDoc`; `Result.entries`/`changes` are clones. A test proves that mutating a returned snapshot throws in strict mode (ESM is strict) and the cache is unchanged.
- Journal (`journal.ts`): `record(doc, actor, op, entryId, before, after, changeId)` appends `{id, at, by, channel, op, entryId, before, after}` (clones), cap `MAX_CHANGES = 200` dropping the oldest; `undo` and `recent` exactly as spec §4 (undo-of-create removes and returns the removed entry; undo-of-delete appends `before` verbatim; undo-of-update restores `before` with `updated/by/channel` restamped; the undo is itself journaled; `sameEntry` compares `encodeEntry` bytes — export the entry encoder from model.ts if it isn't). `recent()` returns `[]` when empty (Go returns nil → JSON null; the TS caller-facing API uses `[]`; note it).

### Replay-safe change IDs (new; decisions.md)
When `replay` is given, the i-th change written by this call gets `replayChangeId(replay.key, i, replay.args)` instead of a ULID (entry IDs of created entries stay ULIDs). Inside the mutation function, **on the doc being written** (so it also sees records written by another replica, and re-checks on retry):
1. Look for a change whose id starts with the 16-char prefix for index 0.
2. Found with the same full id → **replay**: no write. Return `{ entries, changes, snapshot: current }` rebuilt from the journal records with the prefixes for index 0, 1, 2, … (stop at the first missing index); `entries` = each record's `after` ?? `before` (as the original call returned: for delete the deleted entry, for undo-of-create the removed entry). Log at info `replayed change` with the id.
3. Found with a different suffix → **collision**: log at warn `change id collision` with the id and both suffixes; continue as a normal write with ULID change ids.
4. Not found → normal write with the replay ids.
A replay must not touch the store (no `put`): assert that in a test with a counting store wrapper.
