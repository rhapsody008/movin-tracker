## Design (decided)
- **LLM HTTP calls live in `src/llm/`, not in the server, and they are permanent.** T3.1 adds the chat client with pi-ai next to them; the probe does not need pi-ai.
  - `models.ts`: `listModels({baseUrl, apiKey, timeoutMs, signal}) → string[]`, as in §5.1.
    - It sends `GET {baseUrl}/models`.
    - It sends `Authorization: Bearer` only for a non-empty key, and never an empty Bearer.
    - It sorts ids in byte order (`compareBytes`).
    - It throws a `ApiError` whose message is Go's `endpoint returned {status}: {msg}`. Read up to 2000 bytes, prefer `error.message`, trim, and cut at 300 chars plus `…`. Copy the exact rules from `openai.go`/`llm.go`.
  - `probe.ts`: `probe(cfg) → testResult`, the three calls of §5.2.
    - The bodies have exactly Go's field order, and `chat_template_kwargs` appears only when `thinkOnDemand` is set.
    - Use the `probePNG` bytes copied from `server.go:558-559` as a byte array. Never retype base64 by hand; derive it from the Go literal, using the Go harness if that helps.
    - `latencyMs` covers call 2 only. Vision is the image probe, always.
  - Network errors: TS can't reproduce Go's `Get "…": dial tcp …` text. Use the form `Get "<url>": <cause message>` and list it as a known difference.
- **Telegram view with no bot:** status is `{tokenSet:false, running:false, rejected:[]}` and checkin is `{noBot:true, setting:…}`, exactly as in §6.3.
  - Put a small `TelegramStatusSource` interface on `ServerDeps` (`status()`, `checkinStatus()`), optional and null in T2, so T4 can plug the bot in.
  - `tokenSet` comes from a `telegramTokenSet: boolean` dep, which is false in T2.
- **Storage probe:** a `tryLock` mutex, with a 409 on contention. The six steps, the skip and cleanup rules, and the scratch key `_probe/<ULID>.json` follow §6.2. `null` `ifMatch` means create-only.
- **Docs sync:** respond 202 without awaiting. The sync gets no request-linked signal, and a failure is only logged (`document sync from the web page failed`). When the syncer is null, sync returns 404 `Documents are not switched on.`
- **Guide:** a `guide: (() => Promise<Uint8Array>) | null` dep. Raw bytes, `text/markdown; charset=utf-8`, `Cache-Control: no-cache`, no trailing newline added. 404 or 500 as in §6.5.
- **v2 LLM changes (§5.3):**
  - `kind:"claude"` in the body of the models, test or PUT route → 400 with the settings `CLAUDE_MESSAGE`.
  - `kind:"gpt"` → `kind must be openai`.
  - The models route: kind `""` or `"openai"` is OK; anything else → 400 `kind must be openai`, the v2 wording.
  - No `claudeOrigin` anywhere.
- **Key-leak contract:** no response body and no log line contains a stored, env or typed key. Every new log line uses the Go message and fields.

### Go golden transcript
Extend the approach of `tmp/t21-golden`, either as a new mode or as `tmp/t22-golden/main.go`.
- **Setup:** wire Go's real server with a memory store, a fixed clock, a generated Fernet key, and `env LLM` pointing at an in-process Go fake LLM (`httptest`).
- **The script:** about 35 requests covering every T2.2 route's success and error paths:
  - storage view;
  - storage probe on a healthy memory store. Normalise the probe key ULID and the `ms` values;
  - Telegram GET, PUT, a PUT 400 and `useEnv`;
  - check-in PUT, the 400s and `useEnv`;
  - docs off: GET and the sync 404;
  - guide;
  - settings GET, PUT (a URL with a typed key), PUT 400s, test ok, test with no `tool_calls`, models ok, the models 400s, models 502.
- **Output:** write `app/src/server/testdata/transcript-admin.go.json`. The TS test replays it.
- **Go's v1 behaviour on the Claude cases:** leave those requests out of the shared golden. v2 deliberately differs there, so test them TS-only.
- **The fake LLM's port:** the base URL differs per run, so normalise it to `<LLM>`.
- **Normalise also:**
  - Go and Node network-error texts, masked after `Get "<url>": `;
  - `latencyMs`;
  - the `lastWrite.at` timestamp, unless it is deterministic under the fake clock. Check that first.

Everything else must be byte-equal.

### Mutations
At least 8, each on a container copy, each failing a named test. Include:
- the stored key sent to another origin;
- an empty Bearer sent instead of no header;
- `TryLock` replaced by queueing;
- the cleanup-after-failure reset removed;
- docs sync awaited before the response;
- 202 replaced by 200;
- the guide gaining a `\n`;
- the models list unsorted;
- `chat_template_kwargs` always sent.
