# T3.2 — Durable adapter

## Goal
`app/src/durable/adapter.ts` is **the only file that imports pi-durable** (and chord). It owns:
- the harness on SQLite;
- the conversation directory (`web:<email>`, `tg:<chat_id>`);
- the model and connection wiring, plus per-turn thinking;
- the forced final answer round;
- the idle reset and compaction;
- the per-round usage log;
- the history read-back;
- a neutral tool interface and hook points that T3.3, T3.4 and T3.5 fill in.

There are no real tools and no prompt yet: T3.3 and T3.4 own those. T3.2 tests run on pi-ai's faux provider.

## Decisions for the gaps in `durable-api.md` (taken; don't reopen)
- **G1, directory.** Use a session-scoped doc `movin.conversations`: `{ by: Record<key, conversationId> }`. The entry is written in the creating commit through `createConversation({ init })`, so a conversation and its directory entry appear atomically. `conversationFor(key)` either gets the existing conversation or creates one and sets its model.
- **G2, forced answer.**
  - `N = max(cfg.maxToolRounds, 1)`.
  - A `beforeProviderRequest` hook sets `tool_choice: "none"` when `pi.live.run.turns >= N`.
  - `maxTurns: N + 1` stays as a backstop.
  - If a model still calls tools on the forced round, they run and the run ends `turn_limit`. Record that as a known difference from Go, which ignores them. T3.5 maps `turn_limit` to Go's reply rules.
  - Test with faux: with N=2 and a model that always calls tools, request 3 carries `tool_choice:"none"`.
- **G3, the keyless fetch.** Move it into `src/llm/provider.ts`. When the key is empty, `llmModels(cfg)` builds the provider with a wrapped `ProviderStreams` that passes `fetch: withoutAuthorization` and apiKey `"unused"`. `requestOptions` then becomes needed only by `complete.ts`, or is removed if `complete.ts` can use the same models; your choice, but keep one mechanism.
  - Prove on the stub that a request made through the harness with no key carries no Authorization header, and that a request with a key carries `Bearer`.
  - Update `decisions.md` "T3.1".
- **G4, change ID.** The change ID is `sha256(epoch|taskId)`, plus the args-hash suffix (`decisions.md` 2026-11-20); each call is its own task, so no index is needed. T3.3 implements it. T3.2 only exposes `taskId`, `epoch` and `callId` to tools. Record it in `decisions.md`.
- **G5, streaming.** Streaming is commit-granular, about 100 ms partials through `conversation.watch`; accepted. The adapter turns watch updates into neutral events.
- **G6, idle reset and trimming.**
  - Before a submit, if `now - lastActivity > IDLE_RESET_MS` (6 h, a named constant), call `conversation.reset()`. `lastActivity` lives in a doc, written after each run.
  - There is no Go-style 12-turn trim. Compaction is the bound instead: set it so a conversation's context is compacted once it passes `CONTEXT_BUDGET_TOKENS = 48_000` (a named constant, with a comment saying it bounds the cost because the gateway does no prompt caching), keeping about 16k recent tokens.
  - Find in the `.d.ts` how to express a 48k budget, whether through `reserveTokens`/`keepRecentTokens` against the model's `contextWindow` or another way, and prove it with a faux test in which a long conversation triggers compaction.
  - T3.4 re-sends the snapshot after a reset or compaction; T3.2 only exposes "this run starts fresh (first run, after a reset, or after a compaction)" to the prompt hook.
- **G7, the restore path:** T5.3, not now. The adapter must not call `abort()` or `waitForIdle()` before `resume()`; write a comment saying why.
- **G8, failures.** The adapter returns a neutral result:
  - `{ status: "answered", text, stop, usage }`, where `stop` comes from the final message (`stopOf`) so that refusal and max_tokens survive; or
  - `{ status: "failed", reason, detail }`, where the detail text is mapped through `llmError` and so scrubbed.
  
  T3.5 builds Go's replies from this.
- **G10, thinking:** before each submit, `configure({ thinkingLevel: thinkingFor(cfg, think) })`, only when it differs from the stored level.

## The adapter API (neutral; names may be refined, but nothing pi-durable-typed leaves the file)
```ts
interface ToolSpec {           // T3.3 fills these in
  name: string; description: string; parameters: object /* JSON schema */;
  replay: "safe" | "unsafe";
  execute(args: unknown, ctx: { conversationKey: string; taskId: string; callId: string; epoch: string; signal: AbortSignal }):
    Promise<{ text: string; images?: { mediaType: string; data: Buffer }[]; error?: boolean }>;
}
interface AgentHooks {          // T3.3/T3.4 fill these in; T3.2 supplies no-ops
  beforeTool?(key: string, call: { name: string; args: unknown }): Promise<string | undefined>; // block reason
  instructions?(key: string): Promise<string>;                 // system text (rules, documents)
  userContent?(key: string, text: string, fresh: boolean): Promise<string>; // snapshot / delta / date
  transformMessages?(messages: unknown[]): unknown[];          // image placeholders (T3.3)
}
openAgent({ dbPath, settings /* resolve() per use */, log, now?, tools, hooks, retry? }) → Agent
Agent.submit(key, text, { requestId?, think, signal?, onEvent? }) → Promise<RunResult>
Agent.history(key, { limit, before? }) → { items: [{ role: "user"|"assistant", text, at, changes? }], more }
Agent.reset(key); Agent.close(); Agent.closed: Promise<{ kind: "closed" | "failed"; error? }>
```
- **`onEvent`:** emits `{type:"delta", text}` (cumulative or incremental; say which), `{type:"tool", name, status}`, `{type:"reset"}` (a preamble before a tool call is dropped) and `{type:"retry", at, error}`.
- **`requestId`:** passed through for idempotency; T4 uses `tg:<update_id>`.
- **Models and settings:** `models` is a function that calls `settings.resolve()` (cached per settings change, so the key isn't decrypted on every call), and every conversation gets the model set explicitly. `settings.stream.timeoutMs = cfg.timeoutSec*1000`.
- **Usage:** an `afterResponse` hook calls `logLLMCall` once per round, numbering rounds from 1.
- **Epoch:** the session doc `movin.epoch` is created on first open and exposed as `agent.epoch`.
- **`main.ts`:**
  - Open the agent at `config.dataDir` (add `DATA_DIR` to `Config`, default `/data`, with the db at `<dataDir>/harness.db`).
  - Exit with code 1 when it closes `failed`.
  - Close it on shutdown.
  - Don't wire chat routes yet (T3.5).

## Tests (faux provider; temp-file SQLite; injected clock)
- **One turn:** text answer, events, history read-back.
- **A tool round** (a dummy `ToolSpec` echo tool): the tool gets the `taskId`, `callId` and `epoch`; the result goes back to the model; a `beforeTool` block becomes an error result.
- **Forced answer** as above. An unknown tool name becomes an error result to the model.
- **Restart keeps history:** close, reopen the same file, `history(key)` is unchanged, and the next turn's request contains the earlier turns.
- **Crash replay** (child process plus SIGKILL inside a `replay:"safe"` tool, as in T0.2): after reopen and `resume()`, the tool runs again and the run finishes with one answer. Keep it under 30 s.
- **Idle reset:** at +5h59m, no reset (the earlier turns are in the request); at +6h01m, reset (they aren't), and `fresh` is true for the hook.
- **Compaction** triggers past the budget, and `fresh` is true after it.
- **Directory:** two keys give two conversations, and the same key reopened gives the same conversation.
- **Thinking:** `think` true or false gives the right `thinkingLevel` on the request (assert the faux options), and there is no configure commit when the level is unchanged.
- **Retry:** a faux error `other side closed` and then success gives an answer, a `retry` event and two usage lines. `insufficient_quota` gives `failed`/`model_error` with the detail scrubbed of the key. Use `baseDelayMs` small in tests.
- **Usage:** one `llm call` line per round with round numbers.
- **The keyless proof** (G3) on the `src/llm/stub.ts` stub.
- **Mutations (≥8, on copies):**
  - no forced `tool_choice`;
  - no idle reset;
  - reset at the wrong threshold;
  - directory not persisted;
  - Authorization kept when keyless;
  - thinking inverted;
  - usage round off by one;
  - a stray pi-durable import outside the adapter.
