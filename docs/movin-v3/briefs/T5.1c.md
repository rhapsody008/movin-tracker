# T5.1c: check-in tick, `/checkin`, `ci:` callbacks, admin view

## Goal
The morning check-in, working end to end as Go's does:
- the daily tick on T5.1b's durable schedule task;
- the send through the outbox, with the pending note;
- `/checkin` "send now";
- the `ci:` buttons;
- the admin page's check-in status;
- a settings save that re-arms the schedule.

## Design (decided)
**`createCheckin(...)`** lives in `src/tasks/checkin.ts`, with deps `{store, settings, entries, deliver, now, timeZone, log}`. It returns `{spec, tick, status, sendNow}`.
- `spec` is a `ScheduleSpec` named `"checkin"`.
- **The tick** is Go's `CheckinTick` step for step (§1.8), with the per-process `checkinDay` and warn map held in its closure.
- **It returns the next target:**

  | Situation | Next target |
  |---|---|
  | Settings unreadable, chat not allowed, claim held by another copy, or the day released | now + 60 s |
  | On, before the time | today at hh:mm |
  | Off, the day finished, or at/after 20:00 | `nextRun` (when off, use the default time; the 15-minute cap re-reads settings) |

  It re-checks the window on every wake. A sleep armed for 09:30 that fires at 21:00 sends nothing and writes no record.
- **The send:**
  - claim the day, then read the agenda;
  - quiet → `finish(quiet)`;
  - otherwise one `deliver("tg:<chat>", {chat, messageId: 0, group: false}, parts, {note})` using `checkinMessages`, then `finish(sent)`;
  - if `deliver` rejects → `release`.
- **Known differences from Go,** recorded in T5-plan §2.2: "sent" means durably queued, and every ask is listed. Put them in `decisions.md`.
- **Wiring:** only when a Telegram token is set (Go: no token, no check-in). Log `morning check-in loop running` once.

**`/checkin`:**
- `take` first, then Go's three outcomes (§1.6).
- `sendNow` delivers with the note and **never writes `checkin.json`** (§13.5).
- The LLM is never called.

**`ci:` callback:**
- `take`, then auth check 2, then `parseCheckinCallback`.
- The write goes through entries with the precondition checked inside the write: Go's `checkinCallback`, using the TS service's conditional update.
- On success:
  - the toast (`truncate` 190) and the keyboard edit are sent directly and awaited, as for the Undo button;
  - the confirmation `✓ <who>line` with `undoKeyboard` goes through `agent.deliver`.
- On failure: the toasts from §1.7 (`That entry is gone.`, `Couldn't save that…`, and the stale-ask toasts from T5.1a); the buttons stay.

**Admin view:**
- `checkinStatus()` becomes async and returns Go's `CheckinView` (§1.10) in Go's field order.
- `telegramBody()` awaits it.
- With no bot, it still returns `{on: false, noBot: true}`.

**Settings save:** `PUT /api/settings/checkin` calls `agent.schedule.rearm("checkin")` after a successful save (single call site, `admin.ts:~202`). Thread it through the admin options as a callback; admin must not import the adapter.

**Log lines:** every line in t5-spec §6 keeps its text and fields.

## Tests
**All eleven Go tests in §12.1, under Go's names:**
- `TestCheckinCommandAndButtons` (including "the LLM is never called");
- `TestCheckinCapsAskMessages` (9 messages);

- `TestCheckinScheduleCatchUpOncePerDay`;
- `TestCheckinTakesOverACrashedClaim`;
- `TestCheckinTooLateQuietAndFailure`: the failure half restated. `deliver` rejects, the day is given back, and 09:31 sends.
- `TestCheckinButtonAfterTheTaskMoved`;
- `TestCheckinDuringAnAgentTurnKeepsBoth`;
- `TestCheckinChatMustBeAllowed`;
- `TestCheckinTimeFromSettings`, through the durable task and `rearm`: at 09:45 with `10:00` saved, nothing is sent; at 10:30, one is.
- `TestCheckinSkipsWhenSettingsUnreadable`.

**New tests:**
- the 21:00 wake;
- a redelivered `ci:` press writes once;
- a stranger's press gets the toast;
- the field order of the status JSON;
- the next-target table above;
- `rearm` called on a save.

**Crash test:** kill after the claim and before the deliver commit. Reopen with the clock at +11 min. Exactly one check-in goes out, and the record is `sent` with the crashed claim's `since`. Use a new `crash-checkin-child.ts` in `src/telegram`, or extend `crash-bot-child.ts`, and add the case to `src/telegram/crash.test.ts`.

**Mutations (each must fail a named test):**
1. The window check skipped after a wake.
2. A settings failure falling back to the defaults.
3. A refused chat marked finished.
4. `/checkin` writing the record.
5. The precondition checked outside the write.
6. The `take` removed from the command or the callback.
7. The note dropped.
8. `finish` before `deliver`.
