## Design (decided)
- **Static files:**
  - A disk source for the T2.1 `StaticFiles` interface reads `app/static` (configurable via `STATIC_DIR`) on every request, as Go's `os.DirFS` does in dev.
  - Content types: `.html` → `text/html; charset=utf-8`, `.svg` → `image/svg+xml`, `.png` → `image/png`, `.webmanifest` → `application/manifest+json`. The last one is a documented difference: Go sniffs `text/plain` on alpine.
  - `Cache-Control: no-cache` as in Go. No ETag, no Range, no Last-Modified (documented).
  - Reject any name containing `/`, `\` or `..`, or starting with `.`. There is no directory listing.
- **Guide:** read `docs/admin-guide.md` on every request.
  - The path is resolved from `import.meta.url` as `../../docs/admin-guide.md` (the repo root's `docs/`) while the app lives in `app/`. It can be overridden by `GUIDE_FILE`.
  - Missing file → the T2.2 500 path. T7.2 will repoint it.
  - The guide text still describes Claude. Leave it; it is noted for T6/T7.
- **Page edits** in `app/static/index.html`, per the plan:
  - Remove the kind radios, `claudeNote`, `anthHint`, `connKind`/`claudeOrigin`/`targetURL`, and the per-kind think wording. The models, test and save requests no longer send `kind`, or they send `"openai"`.
  - When the view has `legacyKind:"claude"`, show a notice in the LLM tab: "The saved connection is a Claude connection from an older version; it is not used. The connection below comes from the server settings. Saving replaces it."
  - Before saving over it, ask for confirmation with `confirm()`.
  - Keep everything else byte-identical. Report the diff size with `diff static/index.html app/static/index.html | wc -l`.
- **`app/src/main.ts`:**
  - **Commands:** `serve` (the default) and `healthcheck` (GET `http://<addr>/healthz`, 3 s timeout, exit 0 only on 200; `:8080` → `127.0.0.1:8080`, as in Go).
  - **`serve`** builds, in Go's order (spec §8.2), skipping the agent and the bot:
    1. `loadConfig`, then the logger;
    2. the S3 store;
    3. the entries service, then `load()`: a failure is only logged. Start polling every 5 s with an AbortController.
    4. the settings service (with the Telegram and check-in env), plus the two startup warnings;
    5. the poppler converter, the syncer and the docs background schedule. The schedule starts only after `listen` succeeds.
    6. `createServer({...})`, with `telegramTokenSet: config.telegramBotToken !== ""` and `telegram: null`;
    7. `http.createServer` with `headersTimeout = 10_000`, `keepAliveTimeout = 120_000`, `requestTimeout = 0` and `timeout = 0` (set explicitly, and record why in a comment), then `listen` on `LISTEN_ADDR`;
    8. log `listening` with Go's fields, and warn on a non-loopback address.
  - **SIGINT and SIGTERM:**
    - stop the background jobs, `closeStreams()`, and `server.close()`;
    - wait up to 10 s, then `closeAllConnections()` and log a warning, as Go does;
    - log `stopped`, then exit 0.
  - **Structure:** keep `main.ts` thin, with a testable `startServe(config, deps?)` that returns `{address, stop()}`.
  - **Tests:**
    - start on port 0 against the memory store (inject it);
    - `/healthz`, `/readyz`, `GET /` served from `app/static`;
    - `stop()` ends an open SSE stream and resolves;
    - `healthcheck` against the running server returns 0, and returns 1 against a closed port.
- **Compose service `app-ts`:**
  - image `movin-app-test:local` (it has poppler), build as `app-test`, `profiles: [ts]`;
  - `working_dir: /src/app`, volume `.:/src`;
  - `command: ["node", "src/main.ts"]`;
  - `env_file: .env` (optional);
  - environment `LISTEN_ADDR: ":8080"`, `STATIC_DIR: /src/app/static`, `HOME: /tmp`, `XDG_CACHE_HOME: /tmp/.cache`;
  - ports `127.0.0.1:${APP_TS_PORT:-8081}:8080`;
  - user `${HOST_UID:-1000}:${HOST_GID:-1000}`.

  Confirm that `node src/main.ts` runs on Node 24 with type stripping and the `.ts` import paths, and paste the evidence.
- **UI check, `app/tools/ui-check/`:**
  - `run.sh` starts MinIO, then the **TS** app via `docker compose --profile ts run -d --name movin-uicheck-ts -p 127.0.0.1:8090:8080`, with the same MinIO overrides as the Go `run.sh` (`S3_BUCKET=movin-dev`, `S3_PREFIX=dev`, minio keys, `TELEGRAM_BOT_TOKEN=`). It also sets `LLM_BASE_URL=http://host.docker.internal:18090/v1` and a dummy `LLM_API_KEY` if the check needs them. Keep the bucket guard.
  - `check.mjs`: drop the Claude block, and change the OUT path to the repo's `tmp/ui-check-ts/`.
  - `fakellm.py`: drop `/v1/messages`.
  - Run it. Expected: everything passes except the chat steps (no `/api/chat` until T3.5). List every non-PASS line, with the reason for each.
- **Side-by-side on MinIO** (you run this; it never touches the real bucket):
  - Run the Go app with `docker compose run ... app go run ./cmd/movin` on `:8090`, on MinIO `movin-dev/dev`, as Go's `run.sh` does. Run the TS app on `:8091` against the same bucket and prefix.
  - Then, with `curl` and `X-Forwarded-Email` (or `DEV_EMAIL`):
    1. create an entry via TS, and it appears in Go's `GET /api/entries` within 6 s;
    2. patch it via Go, and TS sees it;
    3. undo via TS, then delete via Go;
    4. open TS SSE, write via Go, and the TS stream emits an `entries` event;
    5. GET the TS LLM settings and storage view, then `GET` settings.json from MinIO before and after: the sha256 is unchanged;
    6. PUT the check-in via TS, then GET the Telegram view via Go: Go reads it, and sha256 shows the other sections unchanged.
  - Write this as a script, `app/tools/side-by-side.sh`, which takes the two base URLs. The main session reruns it on the real bucket, so steps that create data must use one named test entry, titled `v3 side-by-side check <timestamp>`, and delete it at the end. Step 6 must be skippable with a flag (`--no-settings-write`), because the real-bucket run must not change settings.
